1. Architecture & System Design Philosophy

The core problem: an endless, unordered, unreliable stream

Microservices emit telemetry forever. Events arrive late and out of order, are delivered at least once (so duplicates happen), some are malformed, and any machine can crash at any moment. The aggregator must still publish correct per-service metrics (count, sum, average, min, max, error rate, throughput) over tumbling and sliding windows with low latency, and keep doing so while it scales and fails.

Architectural invariants of this system

  1. Event time, not arrival time. Every event is placed in the windows of the moment it happened (event_time). Arrival order never changes a result inside the out-of-orderness bound.
  2. Key = service = partition owner. The producer keys every event by service, so all events of a service land on one Kafka partition and one worker owns that service's window state. No state is ever shared between workers.
  3. State and offset move together. A checkpoint writes the window state, the duplicate-detection ids and the next Kafka offset in one atomic RocksDB batch. After a crash the new owner restores that batch and replays from that offset, so every event is counted exactly once in the state although Kafka delivers at least once.
  4. Results are frozen, never silently rewritten. A window becomes final when the watermark passes end + allowed lateness; anything older goes to the dead letter queue with its reason, not into published numbers.
  5. Bad data is isolated, never fatal. Deserialisation, schema, time and lateness failures are routed to telemetry.dlq with the original payload; the pipeline keeps running.
  6. Everything is observable and controllable at runtime. Every component exports Prometheus metrics and JSON logs; every tunable lives in Consul and is applied live; every notable moment is written to a human-readable timeline the lab displays.

Keys decide partitions

The producer sends every event with key = service. confluent-kafka's default partitioner is CRC32(key) mod partitions, so the mapping is fixed and visible:

PartitionServices (CRC32 mod 4)Share of traffic
0order-service, cart-service~29%
1api-gateway, payment-service, user-service~43%
2(none)0%: idle
3product-service, inventory-service~29%
Data skew is a design lesson, not a bug. With four partitions and seven keys one partition is idle and one carries 43% of the load. Adding workers cannot split a partition; you must change the key or the partition count.

Recipe 3: Event-Time Windows: Tumbling & Sliding

Mathematical formulation

Windows are epoch-aligned and half-open [start, end). For an event at time t (ms):

tumbling:  start = t - (t mod size)                 -> exactly 1 window
sliding :  starts = { s : s = t - (t mod slide) - k*slide,  s > t - size }   -> size / slide windows
           size 60 s, slide 10 s  =>  6 windows per event
Source: services/swma/engine/windows.py (lines 9-12)
def tumbling(ts_ms: int, size_ms: int) -> list[tuple[int, int]]:
    """Each event belongs to exactly one tumbling window."""
    start = ts_ms - (ts_ms % size_ms)
    return [(start, start + size_ms)]
Source: services/swma/engine/windows.py (lines 15-26)
def sliding(ts_ms: int, size_ms: int, slide_ms: int) -> list[tuple[int, int]]:
    """Each event belongs to every window with ``start <= ts < start + size``.

    With size=60s and slide=10s that is 6 overlapping windows.
    """
    out = []
    start = ts_ms - (ts_ms % slide_ms)
    while start > ts_ms - size_ms:
        out.append((start, start + size_ms))
        start -= slide_ms
    out.reverse()
    return out
An event at exactly 10:01:00.000 belongs to [10:01:00, 10:02:00), not to the window that ends there. The edge-case suite checks this at 1 ms resolution.

Changing the size or slide in the control plane affects new windows only; open windows keep their boundaries (the window key contains start and end).

Recipe 4: Watermarks, Allowed Lateness & Idle Partitions

Bounded out-of-orderness

watermark(p) = max( watermark(p), max_event_time(p) - bound )      monotonic, per partition
closed  when  end            <= watermark
final   when  end + lateness <= watermark

Defaults: bound 5 s, allowed lateness 10 s, idle timeout 30 s. More lateness means more complete results but later final answers and more state held in memory.

Idle partitions, done safely

If the producer stops, no event moves the watermark and the last windows would never close. So an idle partition's watermark follows the wall clock, but only when the consumer has caught up (position = high-water mark). Otherwise a worker that is merely catching up after a restart would mark its own backlog as "too late".

Source: services/swma/engine/watermark.py (lines 34-41)
    def value(self, wall_ms: int, idle_allowed: bool = True) -> int | None:

        if idle_allowed and self.is_idle(wall_ms):
            idle = wall_ms - self.idle_timeout_ms - self.bound_ms
            candidate = idle if candidate is None else max(candidate, idle)
        if candidate is not None and (self.current is None or candidate > self.current):
            self.current = candidate
        return self.current

Recipe 5: Stateful Incremental Aggregation & Duplicate Detection

The aggregate never stores events, only running values, so memory per window is constant:

count <- count + 1          min <- min(min, latency)       errors <- errors + [status >= 500]
sum   <- sum + latency      max <- max(max, latency)       avg = sum / count   (on emission)
Source: services/swma/engine/aggregate.py (lines 33-52)
    def add(self, latency: float, status: int, ts: int, cpu: float | None = None,
            mem: float | None = None, late: bool = False) -> None:
        self.count += 1
        self.sum += latency
        self.min = latency if self.min is None else min(self.min, latency)
        self.max = latency if self.max is None else max(self.max, latency)
        if status >= 500:
            self.errors += 1
        elif status >= 400:
            self.client_errors += 1
        if cpu is not None:
            self.cpu_sum += cpu
            self.cpu_n += 1
        if mem is not None:
            self.mem_sum += mem
            self.mem_n += 1
        if late:
            self.late += 1
        self.first_ts = ts if self.first_ts is None else min(self.first_ts, ts)
        self.last_ts = ts if self.last_ts is None else max(self.last_ts, ts)

Processing one event

The per-partition engine checks duplicates, reads the watermark, updates every window the event belongs to, and classifies the event (on_time, out_of_order, late_accepted, too_late, duplicate).

Source: services/swma/engine/engine.py (lines 133-181)
    def process(self, event: dict, ts: int, wall_ms: int) -> Outcome:
        eid, service = event["event_id"], event["service"]
        if self.cfg.dedup and eid in self.dedup:
            self.counters["duplicate"] += 1
            return Outcome("duplicate", [], [], self.wm.current)

        wm = self.wm.value(wall_ms, self.caught_up)
        prev_max = self.wm.max_event_ts
        lateness = self.cfg.lateness_ms
        assigned, dropped, any_late = [], [], False
        latency = float(event["response_time_ms"])
        status = int(event["status_code"])
        cpu, mem = event.get("cpu_percent"), event.get("memory_percent")

        for wtype, start, end in self.assign(ts):
            info = {"window_type": wtype, "window_id": window_id(start, end), "start": start, "end": end}
            if wm is not None and end + lateness <= wm:
                dropped.append(info)
                continue
            key = (wtype, service, start, end)
            w = self.windows.get(key)
            if w is None:
                phase = "closed" if (wm is not None and end <= wm) else "open"
                w = WindowState(wtype, service, start, end, phase, event.get("team"), event.get("tier"))
                self.windows[key] = w
            late = wm is not None and end <= wm
            w.agg.add(latency, status, ts, cpu, mem, late)
            w.dirty = True
            self._changed.add(key)
            any_late = any_late or late
            assigned.append({**info, "late": late})

        if not assigned:
            self.counters["too_late"] += 1
            return Outcome("too_late", [], dropped, wm)

        if self.cfg.dedup:
            self.dedup[eid] = ts
            self._dedup_added.add(eid)
        self.wm.observe(ts, wall_ms)

        if any_late:
            kind = "late_accepted"
        elif prev_max is not None and ts < prev_max:
            kind = "out_of_order"
        else:
            kind = "on_time"
        self.counters[kind] += 1
        return Outcome(kind, assigned, dropped, wm)
Duplicate ids are remembered only as long as a duplicate could still change a window: horizon = watermark - max(window size) - lateness. Older ids are garbage-collected.

Recipe 6: Exactly-Once State with RocksDB Checkpoints & S3 Backups

Atomic checkpoint

Every checkpoint_interval (5 s) each worker writes, per partition, only what changed (window states, new and expired dedup ids, watermark, counters, next offset) in one RocksDB WriteBatch, then commits that offset to Kafka. DLQ and result messages are flushed first, so an offset is never committed before its side effects are durable.

Source: services/swma/processor/worker.py (lines 321-339)
    def checkpoint(self, sync: bool = False, only: list[int] | None = None) -> None:
        self.producer.flush(5)  # DLQ + results must be durable before offsets move
        offsets = []
        for p in (only if only is not None else list(self.engines)):
            eng, store = self.engines.get(p), self.stores.get(p)
            if eng is None or store is None:
                continue
            t0 = time.time()
            puts, deletes = eng.drain_changes()
            store.write(puts, deletes)
            M.CHECKPOINT_SECONDS.observe(time.time() - t0)
            if eng.next_offset is not None:
                offsets.append(TopicPartition(settings.TOPIC_EVENTS, p, eng.next_offset))
        if offsets:
            try:
                self.consumer.commit(offsets=offsets, asynchronous=not sync)
            except KafkaException as exc:
                self.log.warning("offset commit failed: %s", exc)
        M.CHECKPOINTS.labels(self.id).inc()

Why this is exactly-once for the state

crash after checkpoint C (offset o_C) and before checkpoint C+1
new owner: state := RocksDB(C) ;  seek(o_C) ;  replay events o_C .. o_crash
=> every event before o_C is in the state once (it was in C),
   every event from o_C on is applied once (replayed into a state that never saw it)
Output to Redis is idempotent (each emission overwrites the window's full result). The metrics.windows topic is at-least-once. Every 30 s a full snapshot also goes to S3; if the local disk is lost the new owner restores from S3 and replays from the snapshot's offset.

Recipe 7: Consumer Groups, Rebalancing, Self-Healing & Autoscaling

The processor container runs a supervisor that starts 1-4 worker processes. Each is a member of consumer group swma-processors; Kafka gives every partition to exactly one member and rebalances when one joins, leaves gracefully (SIGTERM: checkpoint, leave) or crashes (SIGKILL: detected after the 6 s session timeout).

Self-healing

A crashed worker is restarted after restart_delay_s (8 s), long enough to watch the partitions move.

Autoscaling on consumer lag

lag(p) = high_watermark(p) - next_offset(p)          (live, reported by the owning worker)
scale up   if  sum lag > scale_up_lag   and cooled down and workers < max
scale down if  sum lag < scale_down_lag for a whole cooldown and workers > min
Source: services/swma/processor/supervisor.py (lines 255-284)
    def autoscale(self) -> None:
        c = self.cfg.snapshot()
        lo, hi = c["scaling/min_workers"], max(c["scaling/min_workers"], c["scaling/max_workers"])
        if c["scaling/mode"] == "manual":
            new = max(1, min(settings.MAX_WORKERS, c["scaling/desired_workers"]))
            if new != self.target:
                self.record("manual", self.target, new, "desired workers changed in the Control Plane")
                self.target = new
            return
        lag, now = self.lag["live_total"], time.time()
        cooled = now - self.last_scale >= c["scaling/cooldown_s"]
        if self.target < lo or self.target > hi:
            new = max(lo, min(hi, self.target))
            self.record("policy", self.target, new, f"keeping workers within min={lo} / max={hi}")
            self.target = new
            return
        if lag > c["scaling/scale_up_lag"] and self.target < hi and cooled:
            self.record("up", self.target, self.target + 1,
                        f"lag {lag} > scale-up threshold {c['scaling/scale_up_lag']}")
            self.target += 1
        if lag < c["scaling/scale_down_lag"]:
            self.low_since = self.low_since or now
            if self.target > lo and cooled and now - self.low_since >= c["scaling/cooldown_s"]:
                self.record("down", self.target, self.target - 1,
                            f"lag {lag} < scale-down threshold {c['scaling/scale_down_lag']} "
                            f"for {c['scaling/cooldown_s']}s")
                self.target -= 1
                self.low_since = now
        else:
            self.low_since = None

def test_crash_recovery_from_checkpoint_gives_exact_counts():
    events = [ev(i, T0 + i * 100) for i in range(500)]
    # Uninterrupted run
    a = PartitionEngine(0, CFG)
    run(a, events)
    # Crashing run: checkpoint after 200 events, keep processing, then "crash"
    b = PartitionEngine(0, CFG)
    run(b, events[:200])
    b.next_offset = 200
    store = {}
    puts, deletes = b.drain_changes()
    store.update(puts)
    run(b, events[200:350])  # processed but never checkpointed -> lost in the crash
    c = PartitionEngine(0, CFG)
    c.restore(store.items(), T0 + 50_000)
    assert c.next_offset == 200
    run(c, events[c.next_offset:])  # replay from the checkpointed offset
    key = ("tumbling", "payment-service", T0, T0 + 60_000)
    assert c.windows[key].agg.count == a.windows[key].agg.count == 500
